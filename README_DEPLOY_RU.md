# Playerok Universal — исправленный запуск

**Важное различие:** это бот для Telegram и Playerok, работающий в режиме **worker** (Telegram polling), а не HTTP-сайт. `server.py` добавлен специально для хостингов, которые по умолчанию запускают `python /app/server.py`.

## Быстрый запуск

### Windows
1. Установите **Python 3.12.x**, отметьте «Add Python to PATH».
2. Распакуйте ВСЕ файлы архива в одну папку (внутри должны быть `server.py`, `bot.py`, `core`, `tgbot`, `playerokapi`).
3. Запустите **`start.bat`**. Он выбирает Python 3.12, при необходимости устанавливает зависимости и запускает `server.py`.
4. При первом запуске вставьте токен, созданный в @BotFather, и откройте ссылку владельца из консоли.
5. Cookie Playerok и User-Agent настраиваются в Telegram-боте.

### Linux / VPS
```bash
cd /путь/к/распакованному/проекту
chmod +x start.sh
./start.sh
```
Скрипт создаёт `.venv`, устанавливает зависимости и запускает бота. Для ручного запуска: `.venv/bin/python server.py`. **`install.sh` в этом архиве устанавливает только Python-зависимости.** Старый upstream-установщик сохранён в `install_legacy.sh` для справки; не запускайте его, если нужно сохранить эту исправленную сборку.

### Хостинг (например, сервис с папкой `/app`)
- Загружайте **содержимое** архива в `/app` (не дополнительную вложенную папку): `/app/server.py`, `/app/bot.py`, `/app/requirements.txt`.
- Python: **3.12**.
- Build / install command: `python -m pip install -r requirements.txt`.
- Startup / run command: **`python server.py`** (или `python /app/server.py`, если Working Directory — `/app`).
- Тип сервиса: **Background Worker**. Не выбирайте Web Service, если площадка требует HTTP-ответ и открытый порт.
- Секреты (если консоль без `input`): задайте переменную `TELEGRAM_BOT_TOKEN`, а по желанию `PLAYEROK_COOKIES`, `PLAYEROK_USER_AGENT`, `PLAYEROK_PROXY`, `TELEGRAM_PROXY`, `TELEGRAM_API_URL`. Секреты НЕ отправляйте в переписку и не храните в публичном Git-репозитории.
- Сохраняйте каталоги `bot_settings/`, `bot_data/`, `modules/` на постоянном диске, иначе настройки и склад автовыдачи могут пропасть при пересоздании контейнера.
- Если используете Docker, в архиве есть Dockerfile с `WORKDIR /app` и `CMD ["python", "server.py"]`.

### Первичная диагностика
```bash
python server.py --doctor
```
Она проверяет наличие ключевых файлов, синтаксис и библиотеки. Логи процесса также смотрите в консоли и `logs/latest.log`.

### Если хостинг пишет `can't open file '/app/server.py'`
Это означает, что он не видит файл в `/app`, а не то, что API Playerok сломан. Проверьте фактический путь и настройку рабочей директории. После правильной распаковки `server.py` теперь существует.

### Что сохранено
- `playerokapi/` — работа с Playerok, сообщения, товары, сделки;
- `plbot/` — логика автовыдачи, bump, уведомления, фоновые события;
- `tgbot/` — меню, хендлеры, статистика, ответы, список пользователей;
- `core/` — конфигурации, обработка модулей, события и логирование;
- `settings.py`, `data.py`, файлы шаблонов и `.templates/` — совместимость существующих конфигов и подключаемых модулей.

Количество файлов хендлеров и шаблонов намеренно не уменьшалось радикально: множество модулей импортируют их по точным путям, а объединение без полноценного E2E-прогона могло бы сломать действия по сделкам. Основные места запуска и обработки ошибок, наоборот, стали прозрачнее.

### Ограничения проверки
Без действительных Telegram-токена и cookies Playerok невозможно подтвердить реальную работу выдачи, поднятий и подключения. Для проверки автовыдачи используйте тестовый недорогой товар и не включайте авто-вывод средств до проверки.

### Обновление
Для новой установки автоматическое обновление по умолчанию выключено, чтобы внешнее обновление не перезаписало эту исправленную сборку. Если вы вручную включите автообновление в меню, upstream может заменить локальные исправления. Перед обновлением делайте резервную копию `bot_settings/`, `bot_data/`, `modules/`.
